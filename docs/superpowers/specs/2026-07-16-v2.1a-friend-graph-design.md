- 작성일: 2026-07-16
- 상태: 브레인스토밍 승인 → 구현 계획(writing-plans)으로 이어짐
- 상위: v2 소셜 지도(`2026-07-14-social-map-v2-design.md`)의 v2.1 단계를 3슬라이스로 분할한 것 중 **첫 번째**
- 저장소: `~/dev/odagada`

## 1. 목표 / 범위

v2.1(친구 소셜)을 세 독립 슬라이스로 나눈다:
- **v2.1a — 친구 그래프 (이 문서)**: 초대/수락으로 상호 친구를 맺고 목록을 관리한다. 외부 서비스 의존 없음.
- **v2.1b — 소셜 지도 레이어 (다음)**: "친구 N명 저장" 집계 + 친구 저장 오버레이 + 핀 3상태 + 통합 정보카드. (별도 spec)
- **v2.1c — 딥링크 전달 (더 뒤)**: 앱 미설치 친구용 설치→자동연결(Branch 등). (별도 spec)

**이 슬라이스의 완료 정의**: 두 계정이 코드로 실제 친구를 맺고, 각자의 친구 목록에 상대가 뜨고, 삭제할 수 있다. (지도 변화는 아직 없음 — v2.1b.)

**핵심 결정**: 첫 버전은 **외부 딥링크 서비스 없이** 앱 내 초대(코드 입력 기본, 링크는 공유용). 앱이 이미 있는 친구끼리 연결이 끝까지 된다.

## 2. 데이터 모델 (Supabase / Postgres) — 마이그레이션 `0003_friends.sql`

상위 스펙 §8을 재사용·즉시수락 모델에 맞게 **단순화**한다.

```sql
-- 상호 친구: 행의 존재 자체가 친구 관계. 정규화(작은 id=user_a)로 중복행 방지.
create table friendships (
  user_a uuid not null references profiles(id) on delete cascade,
  user_b uuid not null references profiles(id) on delete cascade,
  created_at timestamptz not null default now(),
  primary key (user_a, user_b),
  check (user_a < user_b)              -- 정규화 강제, 자기 자신 금지
);

-- 재사용 초대 토큰. 여러 명이 수락 가능(각자 friendships 행 생성).
create table invites (
  token text primary key,              -- 짧은 랜덤(링크·코드에 들어감)
  inviter_id uuid not null references profiles(id) on delete cascade,
  created_at timestamptz not null default now(),
  expires_at timestamptz,              -- NULL이면 무기한
  active boolean not null default true -- 초대자가 취소 가능
);
```
- 상위 스펙 §8 대비 변경(YAGNI): `friendships.status` 제거(존재=친구, pending 불필요), `invites.accepted_by` 제거(재사용→여러 수락자).

### RLS
```sql
alter table friendships enable row level security;
alter table invites enable row level security;

-- friendships: 당사자만 조회·삭제. 삽입 정책 없음(=직접 삽입 차단; accept_invite 함수로만).
create policy friendships_select on friendships for select
  using (auth.uid() = user_a or auth.uid() = user_b);
create policy friendships_delete on friendships for delete
  using (auth.uid() = user_a or auth.uid() = user_b);

-- invites: 초대자 본인만 생성·조회·수정(취소). 타인은 get_invite_info 함수로만.
create policy invites_owner_all on invites for all
  using (auth.uid() = inviter_id) with check (auth.uid() = inviter_id);

-- profiles: 친구는 서로의 이름·아바타 조회 가능(listFriends 조인에 필요).
-- 0001의 본인 행 SELECT 정책에 더해(정책은 OR로 합쳐짐) 아래를 추가.
create policy profiles_friends_select on profiles for select
  using (
    id = auth.uid() or exists (
      select 1 from friendships f
      where (f.user_a = auth.uid() and f.user_b = profiles.id)
         or (f.user_b = auth.uid() and f.user_a = profiles.id)
    )
  );
```
- **주의**: 이 정책이 없으면 `listFriends`가 친구 프로필(이름)을 못 읽는다. 마이그레이션 `0003`에 반드시 포함.

### DB 함수 (수락은 SECURITY DEFINER로 안전하게)
```sql
-- 수락 전 "OO님과 친구?" 표시용. 친구 아닌 사람에게 다른 정보 노출 없이 초대자 이름·유효성만.
create or replace function get_invite_info(p_token text)
returns table(inviter_name text, valid boolean)
language sql security definer set search_path = public as $$
  select p.display_name,
         (i.active and (i.expires_at is null or i.expires_at > now())
          and i.inviter_id <> auth.uid())
  from invites i join profiles p on p.id = i.inviter_id
  where i.token = p_token;
$$;

-- 토큰 검증 후 상호 친구행 생성(정규화·멱등). 초대받은 사람 권한으로 호출.
create or replace function accept_invite(p_token text)
returns void
language plpgsql security definer set search_path = public as $$
declare v_inviter uuid; v_me uuid := auth.uid();
begin
  select inviter_id into v_inviter from invites
   where token = p_token and active
     and (expires_at is null or expires_at > now());
  if v_inviter is null then raise exception 'invalid_invite'; end if;
  if v_inviter = v_me then raise exception 'self_invite'; end if;
  insert into friendships(user_a, user_b)
  values (least(v_inviter, v_me), greatest(v_inviter, v_me))
  on conflict do nothing;   -- 이미 친구면 멱등
end;
$$;
```
- 두 함수는 `authenticated`에게 execute 권한 부여. 익명은 앱 단에서 로그인 게이트.

## 3. 초대 / 수락 흐름 (외부 서비스 0)

1. **초대자**: "친구 초대" → `invites` 행 생성(짧은 랜덤 토큰) → **코드 + 공유 링크** `io.supabase.odagada://invite/<token>` 표시 → 복사(Clipboard).
2. **초대받은 사람**: "친구 추가" → **코드 입력** → `get_invite_info(token)` → "**OO님과 친구?**" 확인 → **수락** → `accept_invite(token)` → 상호 친구.
3. 딥링크 탭(app_links로 URI 수신→같은 확인 화면)은 **애드온/뒤로**. 코드 입력이 기본·완결 경로.

## 4. 앱 코드

### 4.1 모델 — `lib/friends/friend.dart`
- `Friend { String id; String displayName; String? avatarUrl; }` + `friendFromRow(...)`
- `InviteInfo { String inviterName; bool valid; }`

### 4.2 `FriendRepository` — `lib/friends/friend_repository.dart`
Supabase 클라이언트 주입(목킹 테스트). 메서드:
- `Future<({String token, String link})> createInvite()` — 짧은 랜덤 토큰 생성 후 `invites` 삽입, 링크 조립.
- `Future<InviteInfo> inviteInfo(String token)` — `rpc('get_invite_info', {p_token})`.
- `Future<void> acceptInvite(String token)` — `rpc('accept_invite', {p_token})`.
- `Future<List<Friend>> listFriends(String uid)` — `friendships`에서 내가 낀 행 + profiles 조인, **상대방** 추출.
- `Future<void> removeFriend({required String uid, required String otherId})` — 정규화된 친구행 삭제.
- (선택) `Future<void> revokeInvite(String token)` — `active=false`.

### 4.3 UI — `lib/ui/friends_screen.dart`
- 진입: `AccountButton` 메뉴에 "친구" 추가(앱바가 이미 붐벼 메뉴로).
- 구성: **친구 초대**(→코드·링크·복사), **친구 추가**(코드 입력→확인 다이얼로그→수락), **친구 목록**(이름·아바타·삭제; 비면 "아직 친구가 없어요").
- 로그인 필요(익명이면 로그인 시트) — 저장과 동일 게이트.

## 5. 테스트
- `FriendRepository`: Supabase 클라이언트 목킹 → createInvite 삽입 형태·토큰, listFriends 조인 매핑(상대방 추출), removeFriend 정규화, accept/inviteInfo RPC 호출 인자.
- 모델 매핑 단위 테스트.
- `FriendsScreen` 위젯 테스트(가짜 FriendRepository): 초대 생성 시 코드/복사 노출, 코드 추가 흐름의 확인 다이얼로그·수락, 목록/빈 상태 렌더.
- 마이그레이션·RLS·함수는 사용자가 대시보드 적용 후 실기기 E2E(0001/0002 때처럼).

## 6. 에러 처리
- 잘못된/만료/본인 토큰: `accept_invite`가 예외 → 앱은 "유효하지 않은 초대예요/이미 친구예요" 안내.
- 네트워크 실패: 기존 원칙(사용자 방해 최소화, 재시도 여지). 목록 조회 실패 시 에러 문구.
