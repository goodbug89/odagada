# 주행 중 실시간 주변 정보 추천 앱 — 설계 문서

- 작성일: 2026-07-12
- 상태: 설계 승인 대기 → 구현 계획(writing-plans)으로 이어짐
- 코드네임(잠정): `matjip-app`

## 1. 개요 / 목표

운전 중 차량의 실시간 위치를 기준으로 **주변 맛집을 자동으로 추천**해 지도 위 핀으로 보여주는 모바일 앱. 사용자는 조작 없이도 진행 방향 앞쪽의 좋은 맛집을 지도에서 확인할 수 있다.

장기적으로 맛집은 **여러 "주변 정보 모듈" 중 첫 번째**일 뿐이며, 동일한 구조로 부동산 시세·골프장 정보 등을 켜고 끌 수 있는 **모듈형 플랫폼**으로 확장한다.

## 2. 사용자 & 사용 맥락

- 주 사용자: 여행·맛집 탐방을 즐기며 차로 이동이 잦은 운전자.
- 사용 맥락: **운전 중, 휴대폰을 거치대에 거치.** 손 조작 최소화, 화면 주시 최소화가 핵심 제약.
- 성공 기준(MVP): 주행하면 별도 조작 없이 주변 맛집 핀이 지도에 자동 갱신되고, 핀을 한 번 탭하면 정보(이름·거리·카테고리·평점)와 길찾기로 연결된다.

## 3. 핵심 결정 (확정)

| 항목 | 결정 | 이유 |
|---|---|---|
| 플랫폼 | Flutter (iOS+Android 단일 코드베이스) | 1인 개발 + 다중 모듈 확장에 유리 |
| 데이터 소스 | 카카오 로컬 REST API (음식점 카테고리 `FD6`) | 국내 맛집·POI 커버리지, 무료 쿼터, 키워드/카테고리/좌표반경 검색 |
| 표현 방식 | 카카오맵 + 자동 갱신 핀 | 사용자가 선택한 방식. 조작 불필요하게 설계 |
| 저장소 위치 | OneDrive 밖 (`~/dev/matjip-app`) | git과 OneDrive 동기화 충돌·손상 방지 |

## 4. 아키텍처 — 모듈형 파이프라인

부동산·골프장 확장을 처음부터 염두에 둔 **"위치 → POI Provider → 추천 랭킹 → 지도 핀"** 파이프라인. 맛집은 Provider 인터페이스의 첫 구현체다.

```
GPS 위치·속도·방향
      │
┌─────▼──────────┐   거리 기반 스로틀 (기본 200m 이동마다)
│ Location Engine │   주행/정차 판별
└─────┬──────────┘
      │ LocationEvent(lat, lng, heading, speed)
┌─────▼───────────────────────────────┐
│ POI Provider (공통 인터페이스)        │  ← 확장 포인트
│  ├ RestaurantProvider (카카오 FD6) ✅ │
│  ├ RealEstateProvider (v2)            │
│  └ GolfProvider (v2)                  │
└─────┬───────────────────────────────┘
      │ List<Poi> (후보)
┌─────▼───────────┐  진행방향 앞쪽·거리·평점 가중 랭킹,
│ Recommend Engine │  지나친 곳 제외, 중복 알림 억제
└─────┬───────────┘
      │ List<Recommendation>
┌─────▼──────────┐  카카오맵 + 핀, 탭 시 정보 카드 + 길찾기
│    Map UI       │
└────────────────┘
```

### 설계 원칙
각 유닛은 **하나의 명확한 책임**을 가지고 인터페이스로만 소통하며, 독립적으로 테스트 가능하다. Location Engine과 Recommendation Engine은 GPS/네트워크에 의존하지 않는 **순수 로직**으로 두어 모의 데이터로 단위 테스트한다.

## 5. 컴포넌트 상세

### 5.1 Location Engine
- 책임: 디바이스 GPS 스트림을 구독하고, **일정 이동 거리(기본 200m)마다** `LocationEvent`를 방출. 속도로 주행/정차 상태 판별(정차 시 갱신 빈도 축소).
- 입력: 플랫폼 위치 스트림(`geolocator` 등).
- 출력: `Stream<LocationEvent>` (위도·경도·방위각·속도·타임스탬프).
- 의존: 위치 권한. 로직 자체는 순수(주입된 위치 스트림을 변환) → 모의 트랙 재생으로 테스트.

### 5.2 POI Provider (공통 인터페이스)
```dart
abstract class PoiProvider {
  String get id;               // "restaurant", "realEstate", "golf"
  String get displayName;
  Future<List<Poi>> nearby(LocationEvent loc, {required double radiusMeters});
}
```
- MVP 구현체: `RestaurantProvider` — 카카오 로컬 API `category_group_code=FD6`, 좌표+반경 검색. 응답을 공통 `Poi` 모델(이름·좌표·카테고리·거리·평점(가능시)·주소)로 매핑.
- 확장: 부동산/골프는 동일 인터페이스로 별도 구현만 추가. Provider 목록은 등록(registry) 방식.

### 5.3 Recommendation Engine
- 책임: Provider가 준 후보 POI를 **랭킹·필터**하여 최종 추천 목록 생성.
- 규칙(MVP):
  - **진행 방향 앞쪽 우선**: 현재 heading 기준 전방 부채꼴(±60° 등) 가중.
  - **거리 가중**: 가까울수록 가점, 단 너무 가까워 이미 지나칠 곳은 감점.
  - **평점 가중**(데이터 있을 때).
  - **중복 억제**: 이미 표시했거나 최근 지나친 POI 재알림 억제(최근 표시 집합 유지).
- 순수 로직 → 단위 테스트.

### 5.4 Map UI
- 카카오맵 위젯, 내 위치 따라가기(카메라 팔로우), 추천 핀 렌더.
- 핀 탭 → 하단 정보 카드(이름·거리·카테고리·평점) + **길찾기 버튼**(카카오내비/카카오맵 앱 딥링크).
- 주행 중에는 자동 팝업 없이 핀만 갱신. 상세는 탭 시에만.

### 5.5 Module Selector
- 어떤 Provider(모듈)를 활성화할지 설정 화면. MVP는 맛집만 노출, 구조는 다중 대비.

## 6. 데이터 흐름
GPS → Location Engine(거리 스로틀) → 활성 Provider들 `nearby()` 병렬 호출 → Recommendation Engine(랭킹/필터/중복억제) → Map UI 핀 갱신 → (사용자 탭) → 정보 카드 → 길찾기 딥링크.

## 7. 에러 처리
- 카카오 API 실패/타임아웃: **직전 추천 결과 유지** + 조용한 지수 백오프 재시도. 사용자 방해 최소화.
- Rate limit(429): 백오프 + 갱신 간격 자동 확대.
- GPS 끊김: 마지막 알려진 위치 사용, 복구 시 재개.
- 위치 권한 거부: 안내 화면 + 설정 유도.

## 8. 안전 고려사항 (운전 중)
- 기본 상호작용은 **조작 불필요**(핀 자동 갱신). 운전자가 굳이 화면을 볼 필요 없음.
- 텍스트/버튼은 크게, 개수 최소화. 자동 모달·연쇄 팝업 금지.
- 음성 안내(TTS)는 **v2 옵션**으로 명시(안전성↑). MVP 범위 밖.

## 9. 테스트 전략
- **Location Engine**: 모의 GPS 트랙(좌표 시퀀스) 재생 → 거리 스로틀·주행/정차 판별 검증.
- **Recommendation Engine**: 고정 후보 목록 + heading 입력 → 랭킹·중복억제 결과 단위 테스트.
- **RestaurantProvider**: 카카오 API 응답 목킹 → 매핑 정확성 검증.
- **Map UI**: 위젯 테스트(핀 렌더/탭 콜백). 실제 지도 렌더는 수동 확인.

## 10. MVP 범위 (YAGNI)

### 포함
- 맛집 모듈(RestaurantProvider) 1종
- 위치 추적 + 거리 기반 갱신 + 중복 억제
- 카카오맵 + 자동 추천 핀 + 정보 카드 + 길찾기 딥링크
- Provider/Recommendation 인터페이스는 구현하되 **구현체는 맛집 하나만**

### 제외 (나중)
- 부동산·골프 등 추가 모듈
- 음성 안내(TTS)
- 로그인/계정, 서버 백엔드(초기엔 앱 → 카카오 직접 호출)
- 즐겨찾기/방문 기록/필터

## 11. 확장 로드맵
- v1: 맛집(본 문서 범위)
- v2: 음성 안내 옵션, 즐겨찾기/기록
- v3: 부동산 시세 모듈, 골프장 모듈 (동일 Provider 인터페이스, Module Selector로 on/off)
- 확장 시 서버 백엔드/캐시 도입 검토(쿼터·비용 관리)

## 12. 가정 & 미해결(구현 계획에서 확정)
- **카카오맵 렌더링 방식**: Flutter에서 카카오맵을 JS SDK(WebView 기반 플러그인)로 띄울지, 네이티브 platform-channel 래퍼로 띄울지 — 주행 팔로우 성능을 초기에 검증해 결정. POI 검색은 REST API(순수 HTTP)라 문제없음.
- **평점 데이터**: 카카오 로컬 API가 평점을 직접 주지 않을 수 있음 → 초기엔 거리·방향 위주 랭킹, 평점은 가능한 범위에서 활용/추후 보강.
- **카카오 API 키/쿼터**: 개발용 키 발급 및 일일 쿼터 한도 확인 필요.
- **거리 스로틀 기본값(200m)·전방 부채꼴 각도**: 실주행 튜닝 대상.
