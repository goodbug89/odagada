# 오다가다 v2.1c — 초대 딥링크(https App Link) 설계

- 작성일: 2026-07-20
- 상태: 브레인스토밍 승인 → 구현 계획으로
- 상위: v2.1의 세 번째 슬라이스. v2.1a(친구 그래프)의 "코드 입력" 경로 위에 **링크 탭 → 바로 수락**을 얹는다.
- 저장소: `~/dev/odagada`

## 1. 목표 / 범위

지금 초대 링크(`io.supabase.odagada://invite/<token>`)는 **받는 쪽이 없다** — AndroidManifest에 해당 intent-filter가 없고 `app_links` 의존성도 없어서 탭해도 앱이 열리지 않는다. 게다가 커스텀 스킴은 카카오톡 같은 메신저에서 **링크로 자동 인식되지 않아** 실사용 이득이 없다.

이 슬라이스는 초대 링크를 **https App Link**로 바꿔, 메신저에서 탭하면 앱이 열려 곧바로 "OO님과 친구?" 확인 → 수락까지 가게 한다. 앱이 없으면 안내 웹페이지로 떨어져 코드를 손으로 넣을 수 있다.

**완료 정의**: 초대 링크를 탭하면(앱 설치됨) 앱이 열리고 확인 다이얼로그를 거쳐 친구가 된다. 앱이 없으면 브라우저가 안내 페이지를 열고 코드를 보여준다.

**제외**: iOS Universal Links(iOS 미설정), Branch 등 deferred(미설치→설치→자동연결; 스토어 배포가 전제인데 아직 없음), QR 초대.

## 2. 링크 형식

```
https://goodbug89.github.io/invite/?t=<token>
```

- 토큰을 **경로가 아니라 쿼리 파라미터**로 두는 이유: GitHub Pages는 정적 호스팅이라 `/invite/<token>`은 404가 된다. `/invite/?t=<token>`은 `/invite/index.html`을 서빙하면서 토큰을 전달한다.
- Android intent-filter는 scheme+host+pathPrefix(`/invite`)로 매칭하고, 쿼리는 그대로 앱에 전달된다.

## 3. 호스팅 (사용자가 GitHub에서 적용 — Supabase 마이그레이션과 같은 패턴)

Android App Links는 `assetlinks.json`이 **도메인 루트**에 있어야 하므로 **사용자 Pages 저장소 `goodbug89.github.io`**가 필요하다(프로젝트 Pages `/odagada/`로는 루트에 파일을 둘 수 없다).

저장소에는 `deploy/github-pages/` 아래에 배포용 파일을 두고, 사용자가 그대로 복사해 올린다.

### 3.1 `.well-known/assetlinks.json`
```json
[
  {
    "relation": ["delegate_permission/common.handle_all_urls"],
    "target": {
      "namespace": "android_app",
      "package_name": "com.odagada.app",
      "sha256_cert_fingerprints": [
        "31:28:FD:06:95:7F:35:EF:EA:9F:1D:E3:8D:9C:DA:12:44:25:68:47:39:56:DC:34:17:34:DE:F0:7A:3D:F8:DC"
      ]
    }
  }
]
```
지문은 **현재 디버그 키스토어**(`~/.android/debug.keystore`, alias `androiddebugkey`)의 SHA256이다. 릴리스 서명으로 배포할 때 릴리스 지문을 배열에 **추가**한다(둘 다 나열 가능).

### 3.2 `invite/index.html` (앱 없을 때 폴백)
초대 토큰을 크게 보여주고, 앱에서 "친구 추가"에 넣으라고 안내한다. "앱에서 열기"는 커스텀 스킴으로 한 번 더 시도한다(App Link 검증이 아직 전파되지 않았을 때 유용).

### 3.3 `.nojekyll`
Jekyll이 `.`으로 시작하는 `.well-known/`을 숨기지 않도록 루트에 빈 파일을 둔다.

## 4. Android 설정

`android/app/src/main/AndroidManifest.xml`의 MainActivity에 intent-filter **둘을 추가**한다(기존 LAUNCHER·Supabase OAuth `login-callback` 필터는 그대로 둔다).

```xml
<!-- https App Link (메신저에서 탭 가능, autoVerify로 앱이 바로 열림) -->
<intent-filter android:autoVerify="true">
    <action android:name="android.intent.action.VIEW"/>
    <category android:name="android.intent.category.DEFAULT"/>
    <category android:name="android.intent.category.BROWSABLE"/>
    <data android:scheme="https" android:host="goodbug89.github.io"
          android:pathPrefix="/invite"/>
</intent-filter>
<!-- 커스텀 스킴: 폴백 페이지의 "앱에서 열기" + 기존 공유 링크 하위호환 -->
<intent-filter>
    <action android:name="android.intent.action.VIEW"/>
    <category android:name="android.intent.category.DEFAULT"/>
    <category android:name="android.intent.category.BROWSABLE"/>
    <data android:scheme="io.supabase.odagada" android:host="invite"/>
</intent-filter>
```

커스텀 스킴 필터가 있어야 §3.2의 "앱에서 열기"와 §5.1의 레거시 파싱이 실제로 동작한다(https 검증이 아직 전파되지 않은 동안의 우회로이기도 하다).

## 5. 앱 코드

### 5.1 링크 파싱·생성 — `lib/friends/invite_link.dart` (신규, 순수)

```dart
String buildInviteLink(String token);   // https://goodbug89.github.io/invite/?t=<token>
String? inviteTokenFromUri(Uri uri);    // 초대 링크면 토큰, 아니면 null
```
- `inviteTokenFromUri`는 **두 형식을 모두** 인식한다:
  - 신규: `https://goodbug89.github.io/invite/?t=<token>`
  - 레거시: `io.supabase.odagada://invite/<token>` (기존에 공유된 링크 하위호환)
- 초대가 아닌 URI(특히 Supabase OAuth 콜백 `io.supabase.odagada://login-callback`)에는 **반드시 null**을 반환한다. 로그인 콜백을 초대로 오해하면 안 된다.
- `SupabaseFriendRepository`의 하드코딩된 `_linkPrefix`를 `buildInviteLink`로 교체한다.

### 5.2 공유 수락 플로우 — `lib/ui/accept_invite_flow.dart` (신규)

지금 `FriendsScreen._addByCode` 안에 있는 "초대 확인 → 다이얼로그 → 수락" 로직을 재사용 가능한 함수로 뺀다. 코드 입력과 딥링크가 **같은 UX**를 쓰게 하기 위함(중복 방지).

```dart
/// 토큰으로 초대를 확인하고 사용자 승인 시 수락한다. 수락되면 true.
Future<bool> runAcceptInviteFlow(
    BuildContext context, FriendRepository repo, String token);
```
동작: `repo.inviteInfo(token)` → 무효면 안내 후 false → 유효하면 "OO님과 친구?" 다이얼로그 → 승인 시 `repo.acceptInvite(token)` → 성공/실패 토스트 → 결과 반환. 각 await 뒤 `mounted`(context 유효성) 가드.

`FriendsScreen._addByCode`는 이 함수를 호출하도록 바꾸고, true면 입력칸 비우고 목록 갱신.

### 5.3 딥링크 수신 — `MapScreen`

`app_links` 패키지를 추가한다(`flutter pub add app_links` — 버전은 해석되는 최신 6.x).

`MapScreen`(홈, 항상 마운트되어 있고 `auth`·`friendRepo`를 이미 들고 있음)에서:
- `initState`에서 **앱 시작 시 최초 링크**와 **실행 중 링크 스트림**을 함께 구독.
- 링크 수신 → `inviteTokenFromUri` → null이면 무시(로그인 콜백 등).
- 토큰이 있으면:
  - **로그인 상태**: `runAcceptInviteFlow` 실행 → 성공 시 토스트.
  - **미로그인**: 토큰을 보류(`_pendingInviteToken`)하고 로그인 시트 표시 → 시트가 끝난 뒤 `auth.user != null`이면 보류 토큰으로 이어서 실행, 여전히 미로그인이면 "로그인 후 초대 링크를 다시 눌러주세요" 안내.
  - OAuth 왕복으로 앱이 재시작되는 경우의 자동 이어받기는 **범위 밖**(문서화). 다시 링크를 누르면 된다.
- `dispose`에서 스트림 구독 해제.

## 6. 테스트

- `invite_link` 단위 테스트: 신규 https 형식 파싱, 레거시 커스텀 스킴 파싱, 잘못된 host/pathPrefix → null, `t` 누락 → null, **login-callback → null**, `buildInviteLink`가 신규 형식을 만들고 `inviteTokenFromUri`로 왕복.
- `runAcceptInviteFlow` 위젯 테스트(가짜 `FriendRepository`): 무효 초대 → false·수락 안 함, 유효 초대 + 승인 → `acceptInvite` 호출·true, 승인 취소 → 수락 안 함·false.
- `FriendsScreen` 기존 코드입력 테스트가 리팩터 후에도 통과(회귀).
- 실제 링크 수신·App Links 검증은 온디바이스: `adb shell am start -a android.intent.action.VIEW -d "https://goodbug89.github.io/invite/?t=<token>"`, 검증 상태는 `adb shell pm get-app-links com.odagada.app`.

## 7. 에러 / 엣지

- **assetlinks.json 미배포 상태**: autoVerify 실패 → Android가 앱을 자동으로 열지 않고 브라우저/선택창으로 갈 수 있다. 앱 설치 후 배포가 끝나면 재검증된다(`adb shell pm verify-app-links --re-verify com.odagada.app`). 이 경우에도 `am start`로 앱 경로 자체는 검증 가능.
- 만료·이미 친구·본인 초대: 기존 `accept_invite`/`get_invite_info`의 처리와 토스트를 그대로 쓴다(v2.1a에서 정의됨).
- 토큰이 공개 URL에 담기지만, 토큰은 "가진 사람이 친구가 될 수 있는" 권한이므로 **비공개 공유 전제**는 기존 링크와 동일하다.

## 8. 제외 / 다음

- iOS Universal Links(`apple-app-site-association` + Associated Domains) = iOS 셋업 시 후속.
- Branch 등 deferred deep link(미설치→설치→자동연결) = 스토어 배포 후.
- 초대 revoke UI, QR = 후속.
