# 오다가다 v2.1b-2 — 통합 정보카드(누가 저장 + 메모) 설계

- 작성일: 2026-07-16
- 상태: 브레인스토밍 승인 → 구현 계획으로
- 상위: v2.1b(소셜 지도)의 두 번째 슬라이스. v2.1b-1(친구 핀·3상태) 위에 얹는다.
- 저장소: `~/dev/odagada`

## 1. 목표 / 범위
핀을 탭하면 정보카드에 **"내가 저장(+내 메모)"**와 **"친구 N명 저장 — 이름별 메모"**를 보여준다. 데이터는 이미 준비돼 있다(`friend_saves_near`가 `friend_names[]`·`memos[]` 반환, 내 메모는 `saved_places.memo`). 새 DB·네트워크 없음 — 표시·배선만.

**완료 정의**: 친구가 저장한 곳을 탭하면 카드에 `테스트친구 — "여기 진짜 맛있어요"`가 뜬다. 내가+친구가 겹치면 "✔ 내가 저장(+내 메모)"와 "👥 친구…" 둘 다.

## 2. 데이터 배선 (앱만)

### 2.1 `friendOverlay` 거리 보정 (친구-only 핀 0m 버그)
`friendOverlay(List<FriendSave>, Set<String> existingIds, LatLng center)`로 center를 받아 extraPin의 `distanceMeters = GeoMath.distanceMeters(center, pos)`로 계산(현재 0). MapScreen 호출부도 center 전달.

### 2.2 MapScreen이 친구 저장을 place_id로 보관
`_runSearch`에서 받은 `List<FriendSave>`를 `Map<String, FriendSave> _friendSaves = {fs.placeId: fs}`로 저장. 핀 탭 시 조회용.

### 2.3 핀 탭 → 카드에 친구·내 메모 전달
`_selected`(Poi)에 대해:
- 친구 정보: `_friendSaves[_selected.id]` → `friendNames`/`memos`(정렬된 병렬 배열).
- 내 메모: `_savedPlaces`에서 `placeId == _selected.id`인 것의 `memo`.
카드가 없으면(둘 다 없음) 기존과 동일.

## 3. InfoCard 확장

파라미터 추가: `String? myMemo`, `List<String>? friendNames`, `List<String>? friendMemos`. (기존 `isSaved`로 "내가 저장" 여부 판단.)

렌더(기존 주소·전화·영업시간 아래, 버튼 위):
- **`isSaved`면** "✔ 내가 저장" + `myMemo`(있으면) 한 줄.
- **`friendNames`가 비어있지 않으면** "👥 친구 N명 저장" 헤더 + 각 `i`에 대해:
  - `friendMemos[i]`가 비어있지 않으면 `친구이름 — "메모"`
  - 비어있으면 `친구이름`
- 둘 다 없으면 섹션 없음(현재 카드와 동일).
- 파란 계열 강조로 친구 섹션을 시각적으로 구분(#1B4F9B 아이콘/텍스트).

## 4. 테스트
- `friendOverlay` 거리 보정: center 전달 시 extraPin distance>0 (기존 테스트 갱신).
- `InfoCard` 위젯 테스트: (a) 친구 섹션(이름—메모) 렌더, (b) 내 메모 렌더, (c) 겹침(둘 다), (d) 친구·저장 없으면 섹션 없음.
- MapScreen의 선택→친구/메모 조회는 단순 map 조회 — InfoCard 위젯 테스트로 표시 검증, 실기기 E2E로 흐름 검증(테스트 친구 데이터 사용).

## 5. 에러/프라이버시
- 친구 이름/메모는 `friend_saves_near`(SECURITY DEFINER, 친구·is_public만)에서 온 것 — 남의 것 안 샘.
- 메모가 null/빈 문자열이면 이름만.
