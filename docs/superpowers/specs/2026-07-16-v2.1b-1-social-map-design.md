## 2. 데이터 (마이그레이션 `0004_social.sql`)

### saved_places RLS 확장
친구는 accepted 친구의 `is_public` 저장을 조회 가능(0002 본인정책에 OR 추가). 집계 함수는 SECURITY DEFINER라 이 정책 없이도 동작하지만, 올바른 프라이버시 모델·직접 조회 대비로 둔다.
```sql
create policy saved_places_friends_select on saved_places for select
  using (
    owner_id = auth.uid() or (
      is_public and exists (
        select 1 from friendships f
        where (f.user_a = auth.uid() and f.user_b = saved_places.owner_id)
           or (f.user_b = auth.uid() and f.user_a = saved_places.owner_id)
      )
    )
  );
```

### 집계 함수 `friend_saves_near`
뷰포트(center+radius)의 친구-저장을 place_id로 그룹해 집계. 반경은 bbox 근사(앱이 화면 밖 핀을 컬링하므로 충분). 외부 확장 의존 없음.
```sql
create or replace function friend_saves_near(
  p_lat double precision, p_lng double precision, p_radius double precision)
returns table(
  place_id text, lat double precision, lng double precision,
  name text, category text,
  friend_count int, friend_names text[], memos text[])
language sql security definer set search_path = public as $$
  select sp.place_id,
         max(sp.lat), max(sp.lng), max(sp.name), max(sp.category),
         count(*)::int,
         array_agg(coalesce(p.display_name, '친구') order by sp.owner_id),
         array_agg(coalesce(sp.memo, '') order by sp.owner_id)
  from saved_places sp
  join friendships f
    on (f.user_a = auth.uid() and f.user_b = sp.owner_id)
    or (f.user_b = auth.uid() and f.user_a = sp.owner_id)
  join profiles p on p.id = sp.owner_id
  where sp.place_id is not null and sp.is_public
    and sp.owner_id <> auth.uid()
    and sp.lat between p_lat - (p_radius/111000.0)
                   and p_lat + (p_radius/111000.0)
    and sp.lng between p_lng - (p_radius/(111000.0*cos(radians(p_lat))))
                   and p_lng + (p_radius/(111000.0*cos(radians(p_lat))))
  group by sp.place_id;
$$;
grant execute on function friend_saves_near(double precision,double precision,double precision) to authenticated;
```
- 같은 place_id면 lat/lng/name/category가 동일하므로 `max()`로 대표값. friend_names/memos는 인덱스가 맞는 병렬 배열(같은 array_agg 순서).
- `owner_id <> auth.uid()`로 "친구만"(내 저장 제외). 내 저장은 v2.0d 경로가 담당.

## 3. 앱 코드

### 3.1 모델 — `lib/friends/friend_save.dart`
```
FriendSave {
  String placeId; double lat, lng; String name;
  PlaceCategory bucket;      // category(=bucket id)에서 파생
  int friendCount; List<String> friendNames; List<String> memos;
}
friendSaveFromRow(Map) : category→bucket=PlaceCategory.fromId, 배열 캐스트
```

### 3.2 `SocialRepository` — `lib/friends/social_repository.dart`
추상 + Supabase. `Future<List<FriendSave>> friendSavesNear(LatLng center, double radiusMeters)` → `rpc('friend_saves_near', {p_lat,p_lng,p_radius})` → friendSaveFromRow. (저장소 구현은 E2E — 코드베이스 관례.)

### 3.3 핀 3상태 — `lib/ui/place_pin.dart`
- `CategoryDot`(미저장·친구0): 그대로.
- `SavedPin`을 **일반화** → `PlacePin({Poi poi, bool saved, int friendCount, onTap})`:
  - teardrop(카테고리 색·아이콘)
  - `saved`면 흰 북마크 배지(기존)
  - `friendCount>0`면 **파란 숫자 배지**(우상단, N)
  - `saved && friendCount>0`이면 **파란 링**(겹침 강조)
- 상태 매핑: `!saved && fc==0`→CategoryDot / else→PlacePin(saved,fc).

### 3.4 지도 배선
- `MapController`에 `setFriendCounts(Map<String,int> byPlaceId)` 추가(setSavedIds와 대칭). GoogleMapView가 저장·`_buildPins`에서 각 rec의 poi.id로 fc 조회해 PlacePin/CategoryDot 분기. KakaoMapView no-op.
- `MapScreen._runSearch`가 (검색20 + 내저장 오버레이) 위에 **친구-저장 오버레이 병합**:
  - `socialRepo.friendSavesNear(center,radius)` → FriendSave 목록
  - place_id로 검색결과·내저장과 dedup 병합(친구-only는 Poi로 변환해 추가)
  - `friendCounts = {placeId: friendCount}` 계산 → `setFriendCounts`
  - 친구 저장은 20 상한 무관(오버레이).
- `app.dart`: `SupabaseSocialRepository()` 주입(MapScreen 새 파라미터).
